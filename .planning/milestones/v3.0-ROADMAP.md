# Milestone v3.0: Interactive Workflow

**Status:** ✅ SHIPPED 2026-05-15
**Phases:** 6–7
**Total Plans:** 4

## Overview

Replaced the static step-card and numbered-list layout in the "How It Works" section with a fully interactive stepper UX. Users get an at-a-glance overview of the complete workflow sequence and can explore any step's detail on demand. Both "In the App" and "Importing into xLights" sections use the same BEM component. On desktop the stepper renders as a horizontal rail with a detail panel below; on mobile it becomes a height-animated vertical accordion with per-step collapse/expand chevron controls.

## Phases

### Phase 6: Stepper Foundation

**Goal**: Both workflow sections render as a stepper component with all step titles visible and layout adapts correctly across devices
**Depends on**: Nothing (first phase of v3.0 milestone)
**Plans**: 2 plans

Plans:
- [x] 06-01: CSS foundation — complete BEM stepper rules + 767px mobile accordion block
- [x] 06-02: HTML restructure — replace workflow div with two `.stepper` elements; update animatedEls selector

**Requirements completed:** STEP-01, STEP-05, STEP-06, STEP-07, STEP-08

**Key decisions:**
- `display:contents` on `.stepper__item` makes items layout-transparent — headers land in grid row 1, panels span row 2 via explicit `grid-row` declarations
- Adjacent-sibling selector `.stepper__header--active + .stepper__panel { display: block }` works correctly through `display:contents` because header and panel remain DOM siblings
- `display:none` (not `visibility:hidden`) for inactive panels — removes panel from grid, preventing invisible row-2 occupation
- Old workflow CSS commented out (not deleted) as safety net during transition

### Phase 7: Stepper Interaction

**Goal**: Users can click any step to read its detail, with only one step open at a time and Step 1 pre-expanded on scroll entry
**Depends on**: Phase 6
**Plans**: 2 plans

Plans:
- [x] 07-01: JS stepper controller — click/collapse handler, auto-expand IntersectionObserver, keyboard navigation
- [x] 07-02: Human browser verification — all 12 checks passed across desktop and mobile viewports

**Requirements completed:** STEP-02, STEP-03, STEP-04

**Key decisions:**
- Two separate IIFE script blocks for click handler vs auto-expand + keyboard — independently verifiable
- Auto-expand duplicates minimal open logic inline rather than calling cross-IIFE `activateStep` — avoids coupling
- Arrow keys move focus only; Enter/Space activate (native button behaviour) per D-08
- Direction determined at keydown time via `window.innerWidth > 767` per D-07 — no resize listener

**Bugs found and fixed during human verification:**
1. Panel immediately closed after expand — `transitionend` was clearing inline height to `''`, falling back to CSS `height: 0`. Fixed: set `height: 'auto'` instead.
2. Jump at end of expand animation — `scrollHeight` measured before padding applied, so animated target excluded 16px bottom padding. Fixed: set padding before measuring.

**Post-close enhancements (not in original plans):**
- Added chevron expand/contract toggle icon on mobile accordion headers
- Mobile accordion starts fully collapsed (all panels closed on page load)
- Resize boundary sync: when crossing 768px desktop↔mobile, active panel height is re-synced via JS

## Milestone Summary

**Key Decisions:**

| Decision | Rationale |
|----------|-----------|
| CSS Grid + `display:contents` for stepper layout | Headers and panels from different DOM nesting levels need to land in the same grid rows — `display:contents` makes `.stepper__item` layout-transparent |
| Phase split: CSS/HTML foundation (6) then JS interaction (7) | Static structure first, behavior layered on top — cleanly separable concerns |
| Adjacent-sibling selector for desktop panel visibility | Works through `display:contents`; no JS needed for desktop tab switching layout |
| Separate IIFEs for click handler vs auto-expand + keyboard | Independently committable, testable, and revertable without affecting the other script block |

**Issues Resolved:**
- Static `:first-child` CSS rule conflicted with JS-managed state on mobile — removed in Phase 7
- `height: auto` required after open animation (not clearing inline style to `''`) — discovered and fixed during human verification
- Padding-before-measure pattern required to prevent jump at end of expand — discovered and fixed during human verification
- Mobile resize from desktop left active panel collapsed (no JS height) — fixed post-close with resize boundary sync

**Issues Deferred:**
- VERIFICATION.md files not formally updated to `passed` after human verification — acknowledged at milestone close
- HUMAN-UAT.md partial status in phases 04/05/06 — acknowledged at milestone close

**Technical Debt Incurred:**
