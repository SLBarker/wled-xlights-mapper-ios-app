  <name>Task 1: Browser verification — click expand/collapse, auto-expand, keyboard nav</name>
  <read_first>
    - .planning/phases/07-stepper-interaction/07-CONTEXT.md (D-01 through D-09 — the acceptance behaviours)
    - .planning/phases/07-stepper-interaction/07-01-SUMMARY.md (what was implemented in Plan 01)

  <what-built>
    Plan 01 added a JS stepper controller to index.html with three behaviours:
    1. Click handler: expand clicked step, collapse previously open step, update aria-expanded and .stepper__header--active, animate height on mobile
    2. Auto-expand observer: fire-once per .stepper element on viewport entry, expands Step 1
    3. Keyboard handler: arrow keys cycle focus between headers; Enter/Space activates (native button default)

    The static CSS :first-child open rule was also removed so JS manages all state.
  </what-built>
  <how-to-verify>
    Open index.html directly in a browser (file://) or via a local server.

    **Desktop (viewport ≥ 768px):**

    1. Scroll to the "How It Works" section. Verify Step 1 of both steppers is highlighted (accent-coloured badge, active border indicator) without any click. This confirms STEP-04.

    2. Click Step 2's header in the "In the App" stepper. Verify:
       - Step 2's detail panel becomes visible below the rail
       - Step 1's panel disappears
       - Only one panel is visible at a time
       This confirms STEP-02 and STEP-03.

    3. Click Step 3, Step 4, Step 5 in sequence. Each click should reveal that step's panel and hide the previous one.

    4. Repeat steps 2–3 for the "Importing into xLights" stepper.

    5. Tab to the first stepper header. Press ArrowRight. Verify focus moves to Step 2's header (visible focus ring). Step 2's panel should NOT expand automatically (per D-08). Press Enter — panel should expand. Press ArrowLeft — focus returns to Step 1.

    **Mobile (resize viewport to ≤ 767px or use browser DevTools device emulation):**

    6. Scroll to the "How It Works" section. Verify Step 1's panel is already open (expanded accordion item) without any tap. Step 1's badge should be accent-coloured. This confirms STEP-04 on mobile.

    7. Tap Step 2's header. Verify:
       - Step 2's panel slides open with height animation
       - Step 1's panel slides closed
       - Transition is smooth (not instant)
       This confirms STEP-02 and STEP-03 on mobile.

    8. Tap several more steps in sequence. Each tap should open the tapped step and close the previous one. No two panels should be open simultaneously.

    9. Verify the content padding inside an open panel is visible (not zero).

    10. On mobile, press ArrowDown while a header is focused. Verify focus moves to the next header without the panel expanding.

    **Edge cases:**

    11. Tap/click the already-active step. Verify nothing changes (no-op — the step stays open).

    12. Scroll away from the "How It Works" section and scroll back. Verify the stepper remains in whatever state the user left it (does NOT re-expand Step 1 on second entry — confirms fire-once per D-01).

    **Expected results for each check:**
    - Step 1 pre-expanded on page load (scroll into view): PASS
    - Clicking inactive step shows its panel: PASS
    - Previously open panel closes: PASS
    - Arrow key moves focus without expanding: PASS
    - Mobile height animation is smooth: PASS
    - Fire-once (no re-expand on second scroll-in): PASS
  </how-to-verify>
  <acceptance_criteria>
    - All 12 verification steps above pass without error
    - No JavaScript console errors visible in DevTools during any interaction
    - On mobile, the panel height animation completes smoothly (no jump to height:0 or height:auto without transition)
    - On desktop, switching steps does not cause layout shifts in surrounding page content
    - Step 1 is expanded on first viewport entry in BOTH stepper instances (not just the first one)
  </acceptance_criteria>
