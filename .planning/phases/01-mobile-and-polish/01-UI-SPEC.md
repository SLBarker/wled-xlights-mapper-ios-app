## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, hairline padding |
| sm | 8px | Compact element spacing, gap between hamburger bars |
| md | 16px | Default element spacing, nav horizontal padding |
| lg | 24px | Section inner padding on mobile |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Nav bar height: **56px** (already set in `.site-nav__inner`) — retain as-is.
- Touch targets (hamburger button): minimum **44px × 44px** to meet WCAG 2.5.5 (AAA) and Apple HIG minimum tap target.
- Mobile section padding: reduce `.section` padding from `100px 2rem` to `64px 1.25rem` at max-width 768px. The 1.25rem horizontal padding prevents content reaching the screen edge.

Source: existing spacing from `index.html`, mobile exception derived from MOBL-01 requirement.

## Hamburger Nav Toggle — Full Component Spec

This is the only new interactive component in Phase 1.

### Trigger Element

```
Element:   <button> (not <a>, not <div>)
Class:     .site-nav__toggle
Location:  Inside .site-nav__inner, right-aligned, replacing .site-nav__links on mobile
Visible:   Only at max-width: 768px (display: none on desktop)
Size:      44px × 44px (touch target)
Background: transparent
Border:    none
Cursor:    pointer
```

### Icon (inline SVG, 3 horizontal bars)

```
SVG viewBox:   0 0 24 24
Stroke:        var(--text)   [bar colour at rest]
Stroke-width:  2
Line-cap:      round
Bar dimensions: each bar is a <line> element
  Bar 1 (top):    x1="3" y1="6"  x2="21" y2="6"
  Bar 2 (middle): x1="3" y1="12" x2="21" y2="12"
  Bar 3 (bottom): x1="3" y1="18" x2="21" y2="18"
aria-hidden: true  (button label carries the accessible name)
```

Close state icon: Replace SVG with a single X (two diagonal lines) when menu is open.
- Alternative: CSS transform the bars into an X to avoid DOM swap.
- Recommended approach: CSS transform (no JS DOM mutation needed).

### ARIA Contract

```
aria-label:    "Open navigation menu"  (when closed)
               "Close navigation menu" (when open)
aria-expanded: "false" (when closed) / "true" (when open)
aria-controls: "site-nav-menu"  (ID of the <ul> element)
```

The `<ul>` receives:
```
id:            "site-nav-menu"
```

### Drawer Behaviour

```
Trigger:       Tap/click .site-nav__toggle
Open state:    .site-nav__links displays as a vertical stack below the nav bar
Closed state:  .site-nav__links is hidden (display:none or height:0 with overflow:hidden)
Animation:     max-height transition from 0 → auto equivalent using max-height trick
               Duration: 0.35s (matches --transition duration)
               Easing:   cubic-bezier(0.25,0.46,0.45,0.94) (matches --transition)
Close triggers: (1) tap toggle again, (2) tap any nav link, (3) press Escape key
```

### Mobile Nav Menu Layout (open state)

```
Position:      block flow — pushes page content down (not overlay/fixed)
Background:    rgba(245,245,247,0.97) with backdrop-filter: blur(20px) saturate(180%)
               Matches nav bar background for visual continuity
Border-bottom: 1px solid rgba(0,0,0,0.06)  (matches .site-nav existing border)
Padding:       8px 0 16px 0
Link layout:   vertical stack, full-width
Link padding:  0.6rem 1.25rem  (wider horizontal padding than desktop for touch comfort)
Link font:     0.9375rem (15px) / weight 500  (slightly larger than desktop 13px for readability)
Link colour:   var(--muted) at rest, var(--accent) on hover/focus-visible
CTA link (.site-nav__cta):
  Display as block, margin: 8px 1.25rem 0
  Retains pill shape (border-radius: 20px)
  Background: var(--accent), colour: #fff
  Text align: center
```

### Focus Management

```
When menu opens:  move focus to the first <a> in #site-nav-menu
When menu closes via Escape: return focus to .site-nav__toggle
When menu closes via link tap: focus follows natural navigation (do not forcibly move)
Focus ring:       outline: 2px solid var(--accent), outline-offset: 2px
                  Applied via :focus-visible on both toggle button and nav links
```

### Keyboard Interaction

```
Escape:   Close menu, return focus to toggle
Tab:      Standard tab order through open menu items
Enter / Space: Activate toggle (browser default for <button>)
```

## Lazy Video Loading (PERF-01)

No visible UI change. Contract is behavioural only.

```
Mechanism:    IntersectionObserver (vanilla JS, already used in codebase for scroll animations)
Trigger:      rootMargin: "200px"  (start loading when video is 200px below viewport)
Initial HTML: <video> elements have src attribute removed on page load
              src is written back by the observer when the element enters range
Fallback:     If JS is unavailable, video renders without src (shows nothing — acceptable;
              the page degrades gracefully, no broken-image placeholder needed)
No poster attribute required for Phase 1 (v1 scope).
```

## Bug Fixes — Visual Contract

### MOBL-03: Nested DOM Fix

Current state: `phone-bezel__screen` is nested inside another `phone-bezel__screen`, and `phone-bezel__notch` is duplicated inside the nested screen. This creates a visible double-border artefact on some screens.

Fix contract: Each `.phone-bezel` must have exactly ONE `.phone-bezel__screen` element as a direct child of `.phone-bezel__frame`. The notch must appear exactly once, as the first child of `.phone-bezel__screen`. The `<img>` or `<video>` is a sibling of the notch inside `.phone-bezel__screen`.

Correct DOM structure:
```
.phone-bezel
  .phone-bezel__frame
    .phone-bezel__screen
      .phone-bezel__notch [aria-hidden="true"]
      <img> or <video>
  .phone-bezel__caption
```

Affected instances: hero phones 1 and 3, features section phones for "discovery" and "preview" features (confirmed 4 instances with nested screens in the markup).

### MOBL-04: Alt Text Fix

Current state: Three `<img>` elements in the hero phone mockups share identical alt text: "App screenshot showing the controller connect screen with mDNS discovery list".

Fix contract: Each image must have a unique, accurate description:

| Image src | Required alt text |
|-----------|-------------------|
| `resources/screenshot/connect.jpeg` | `App screenshot showing the WLED controller connect screen with mDNS discovery list` |
| `resources/screenshot/ar.jpeg` | `App screenshot showing the AR scanning view with gray-code pattern detection overlay` |
| `resources/screenshot/preview.jpeg` | `App screenshot showing the 3D LED preview with quality tier colour overlay` |

Video `aria-label` fix: Both `<video>` elements currently share the same `aria-label`: "Screen recording of the AR scan in progress, showing gray-code pattern cycling across LEDs". The 3dpreview.mp4 video must be updated:

| Video src | Required aria-label |
|-----------|---------------------|
| `resources/video/discovery.mp4` | `Screen recording of automatic mDNS controller discovery and segment selection` |
| `resources/video/3dpreview.mp4` | `Screen recording of interactive 3D LED preview with pan, zoom, and rotate controls` |

### MOBL-05: Grammar Fix

| Location | Current text | Corrected text |
|----------|-------------|----------------|
| Step 04 copy (how-it-works section) | Contains "it's" (contraction) | Replace with "its" (possessive) |

## Interaction Summary

| Interaction | Trigger | Response | Duration |
|-------------|---------|----------|----------|
| Open nav | Tap hamburger button | Drawer slides down, focus moves to first link | 350ms ease |
| Close nav via toggle | Tap hamburger button again | Drawer slides up, focus returns to button | 350ms ease |
| Close nav via link | Tap any nav link | Drawer closes immediately (no animation needed), page scrolls to section | 0ms (link navigation takes over) |
| Close nav via Escape | Keyboard Escape key | Drawer slides up, focus returns to button | 350ms ease |
| Nav link hover | Mouse hover | Colour → `--accent`, background → `rgba(0,113,227,0.07)` | 350ms ease |
| Nav link focus-visible | Keyboard focus | Same as hover, plus 2px accent outline | 350ms ease |
| Scroll animations (existing) | IntersectionObserver | `.visible` class added — opacity 0→1, translateY 40→0 | 500–600ms existing |
| Video lazy load (new) | IntersectionObserver (200px rootMargin) | `src` attribute written to `<video>` | Immediate (load starts async) |
