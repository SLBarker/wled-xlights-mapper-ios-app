<!-- Key CSS contracts this plan ESTABLISHES for Plan 02 (JS) to consume. -->

The JS `goTo()` function in Plan 02 will rely on these CSS contracts:

1. Slide width remains 240px (unchanged):
   ```css
   .hero-carousel__slide { flex: 0 0 240px; width: 240px; }
   ```
   → JS uses `translateX(-${current * 240}px)`

2. Active modifier class exists and overrides opacity:
   ```css
   .hero-carousel__slide { opacity: 0.5; transition: opacity var(--transition); }
   .hero-carousel__slide--active { opacity: 1; }
   ```
   → JS toggles `.hero-carousel__slide--active` on each slide

3. Track-wrap is wider than slide (peek shows on both sides):
   ```css
   .hero-carousel__track-wrap { overflow: hidden; width: 380px; }
   ```
   The slide is centred inside the track-wrap by the CSS flexbox `align-items: center` on `.hero-carousel`; horizontal centring of the active slide within the 380px viewport is achieved naturally because `(380 - 240) / 2 = 70px` of peek shows on each side when `translateX(0)` puts the first slide at the left edge of the track. The track itself starts at the left edge of the wrap; the active-centring effect comes from `goTo()` applying a negative offset that pulls slide N into the centre slot. The 70px of peek to the left is the previous slide's right edge; 70px of peek to the right is the next slide's left edge.

4. Arrows are absolute-positioned (not flex children):
   ```css
   .hero-carousel__arrow { position: absolute; top: 50%; transform: translateY(-50%); }
   #carousel-prev { left: 13px; }
   #carousel-next { right: 13px; }
   ```
   → JS only needs to toggle `visibility` on these buttons; positioning is handled in CSS.

5. The viewport is the containing block for absolute arrows:
   ```css
   .hero-carousel__viewport { position: relative; /* gap removed */ }
   ```
